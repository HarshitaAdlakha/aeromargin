Grading

Code graders only. 133 checks, before any model ran.

  • Accepts every reference solution, and reformatted versions of it (commas, units, case)
  • Accepts every number nudged to 80% of its tolerance: no false fails from rounding
  • Rejects each critical field moved past tolerance, one at a time
  • Rejects 24 trap answers, each a specific mistake an engineer would recognise
  • Rejects gaming: echoed templates, “pass|fail” hedges, lists of candidates, a second JSON
  • Oracle run: all 10 reference solutions pass through the full harness
Grades the final JSON, not the path · partial credit + critical fields05

Hot take

The gap isn't arithmetic.
It's recall versus re-derive.

The same model is right on every trial when it reasons, and confidently wrong when it answers from memory. For engineering teams, the reasoning setting matters more than the leaderboard. Ask for the governing case and every load's direction before any number, as a senior checker would. To close the gap for good, train on reversed defaults: robustness.py generates them.
